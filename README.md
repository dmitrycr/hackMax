# HackMax — «До подачи»

Каркас сервиса предварительной проверки документов в MAX.
**Go** управляет приложением и правилами, **Python** читает документы и выполняет
OCR, **React** предоставляет мини-приложение и кабинет методиста.

## Текущее состояние

Это инфраструктурный каркас. Реализованы:

- экран состояния на React / TypeScript / MAX UI;
- Go API: `/healthz`, `/readyz`, `/api/v1/system`;
- подключение PostgreSQL, миграции приложения и River;
- Go worker с реальным заданием проверки доступности Python;
- внутренний FastAPI с проверкой сервисного токена;
- контракт будущего извлечения документов;
- Docker Compose, локальные секреты, lock-файлы, проверки и CI.

**Следующий этап:** вход через MAX, загрузка файлов, версии комплектов,
извлечение DOCX/PDF, OCR, правила ведомства, замечания и экспорт.
Пакеты для этих областей выделены, но предметная логика ещё не реализована.
`POST /internal/v1/extract` намеренно возвращает **501 `extraction_not_implemented`**.
Установленные библиотеки OCR не означают готовую проверку сканов.

## Быстрый запуск

Нужны Docker с Compose, Python 3 для создания `.env` и `make`.

```sh
make up
```

Команда создаёт `.env` со случайными локальными секретами, собирает образы,
выполняет миграции и запускает компоненты. Существующий `.env` не перезаписывается.
Первая сборка скачивает образы и зависимости и может занять несколько минут.

Открыть **http://localhost:8080**. Порты привязаны к `127.0.0.1`.

```sh
make probe           # Реальная проверка PostgreSQL → River → Go worker → Python
docker compose ps    # Состояние контейнеров
make logs            # Журналы сервисов
make down            # Остановка; постоянные тома сохраняются
```

Публичный HTTPS-домен и регистрация бота потребуются для работы внутри MAX.
Текущая конфигурация предназначена для локальной разработки. `GATEWAY_ADDRESS`
подготовлен для Caddy, но одного изменения адреса недостаточно: нужно настроить
DNS, доступные порты, авторизацию и исходящий доступ Go к MAX. Сейчас серверная
сеть изолирована, интеграция с MAX ещё не активна.

## Команды разработчика

Локальные инструменты: Go 1.25+, Python 3.12, uv 0.11.6, Node.js 22.12+ и npm.
Точные версии библиотек записаны в `go.sum`, `uv.lock`, `package-lock.json`.

```sh
make check               # Go-тесты/vet, Python lint/тесты, сборка UI, проверка Compose
make generate-contracts  # Экспорт схем из Python-кода
make sqlc                # Генерация Go-методов из SQL через sqlc 1.29.0
```

Изменение Python-контракта требует обновления экспортированных файлов; CI
проверяет, что генерация не оставляет различий. OpenAPI описывает текущий HTTP 501;
`extraction-result.schema.json` описывает планируемый результат, пока не возвращаемый API.

Для разработки UI с горячим обновлением, при уже запущенном Compose:

```sh
cd apps/web
npm ci
npm run dev
```

Vite перенаправляет `/api` на `127.0.0.1:8080`. Браузер не получает токены MAX
или Python. Полные документы и персональные данные не добавляются в Git.

## Проверки перед развитием бизнес-логики

1. Подключить серверную проверку данных запуска MAX и доступ к собственным комплектам.
2. Реализовать закрытое хранилище, ограничения загрузки, версии и удаление файлов.
3. Добавить один профиль DOCX в Python и сквозной вызов из Go worker.
4. Добавить одно подтверждённое правило на Go и привязать замечание к исходному полю.
5. Расширять контрольный набор, затем подключать PDF и OCR отдельными профилями.

Архитектура заложена; создание каркаса не подтверждает качество OCR или
соответствие документов требованиям ведомства.
