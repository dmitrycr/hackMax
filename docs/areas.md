# Области разработки

## 1. Интерфейс — `apps/web`

Общий React-проект для мини-приложения и кабинета методиста. `App.tsx` сейчас
отображает состояние инфраструктуры. `shared/api` отвечает за HTTP-вызовы.
В `features` будут сгруппированы пользовательские сценарии.

Здесь находятся отображение прогресса, загрузка, карточки замечаний и формы
настройки. Решения о корректности документов принимает сервер.

## 2. Go API — `services/backend/cmd/api`

Точка входа HTTP-сервера. Читает настройки, создаёт подключения, запускает
маршруты и корректно завершает работу. Маршруты находятся в `internal/transport/http`.

API должен проверять пользователя и права перед доступом к файлам. Пока
существуют только технические маршруты состояния.

## 3. Предметные модули — `services/backend/internal/modules`

| Пакет | Будущая ответственность |
|---|---|
| `identity` | Пользователи, сессии, роли заявителя и методиста |
| `packages` | Комплекты, загрузки, версии файлов, контрольные суммы и удаление |
| `requirements` | Услуги, бланки, применимость, версии и публикация требований |
| `checks` | Запуски проверки, снимки входных данных, история и замечания |
| `rules` | Детерминированные проверки полей, расчётов и согласованности |
| `reports` | Экспорт проверенных файлов, HTML-отчёта и манифеста |

На этапе каркаса здесь находятся описания границ пакетов. Пустая имитация CRUD
и недостоверные демонстрационные проверки не добавлены.

## 4. Интеграции — `services/backend/internal/integrations`

`processor` — работа с внутренним Python API, сервисный токен и тайм-ауты.
`max` — место для официального Go SDK, событий бота и проверки данных запуска.
Токены должны оставаться в серверной конфигурации.

## 5. Фоновые задания — `services/backend/internal/jobs`

River-обработчики. Сейчас реализован `system.processor_probe` для проверки
соединения с Python. Будущие задания извлечения и проверки должны быть устойчивы
к повторам и перезапускам. Точка запуска процесса — `cmd/worker`.

## 6. Документы и OCR — `services/document-processor`

Python-компонент извлечения. Чтение форматов — `extractors`, распознавание —
`ocr`, знание структуры конкретного бланка — `profiles`.
Возвращает прочитанные данные и происхождение каждого значения. Требования
ведомства, публикация правил и решения о несоответствиях находятся в Go.

## 7. Данные — `db` и `internal/platform`

`db/migrations` — история изменений БД; миграции встраиваются в Go-бинарник.
`db/queries` — SQL для sqlc. `platform/postgres` создаёт пул соединений.
`platform/storage` — граница будущего файлового хранилища.
River управляет собственными таблицами через свою систему миграций.

## 8. Контракты — `contracts`

Общий язык Go и Python. Прежде чем менять форму ответа одного компонента,
нужно обновить схему и соответствующую сторону взаимодействия. Десятичные
значения передаются строками, координаты должны ссылаться на исходный документ.

## 9. Инфраструктура и качество

`compose.yaml`, Dockerfile и `deploy` описывают воспроизводимый запуск.
`scripts` содержит вспомогательные команды. `.github/workflows` — CI.
`tests/fixtures` предназначен для синтетических документов; тесты отдельных
компонентов находятся рядом с их кодом.

## Распределение на троих

1. Интерфейс, пользовательские сценарии и кабинет методиста.
2. Go API, MAX, данные, очередь и формальные правила.
3. Python, извлечение, OCR и контрольные документы.

Контракты, требования, интеграцию и проверку сквозного сценария команда делает совместно.
